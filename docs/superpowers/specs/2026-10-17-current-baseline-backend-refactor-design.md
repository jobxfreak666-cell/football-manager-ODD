## 3. 模块边界

新增 `counseling_application.py`、`medical_application.py`、`canteen_application.py`，各自只负责对应完整用例。与已完成的 `match_intelligence_application.py` 一样，新服务通过窄 Runtime Protocol 访问现有状态，通过冻结 I/O 数据类调用外部函数；不导入 `fm_odds_web`、原生读取模块或启动入口。

`LocalOddsState` 唯一持有状态、锁、会话/账户身份、线程及调度。原方法签名继续存在，作为兼容门面；每次调用重新绑定当前模块依赖，保留原先替换函数的测试及调用方。不得产生另一套账户状态、缓存或任务调度器。

继续复用已有 `AccountApplicationService`、`MatchIntelligenceApplicationService`、`PlayerDepartureApplication`、`player_effects`、`state_patches`、`state_publication` 和 `api_routing`。不重复提取账户、情报或路由服务，不引入通用依赖注入容器。

`club_economy.py` 继续持有账户领域与持久化真值；`club_reader.py` 继续持有原生读取、验证写入和回滚。此次不切开账户锁、迁移 schema 或重写金额/事务算法。

- 保持现有 API、响应字段、错误语义、存储格式、价格、冷却及 FM24/FM26 支持范围。
- 保持锁顺序、锁覆盖范围、账户绑定、预期旧值校验、写后回读和恢复调用顺序。
- 不操作真实 FM、不安装 Hook、不修改真实账户/存档、不启动产品 EXE；不自动构建发布包、提交或推送。
- 本轮默认不改 UI；必要的可见调整须单独说明并提供真实前端渲染的预览图。字号不小于 13px，相关文案覆盖 11 种语言。

- 缺陷修复与行为保持的迁移分开；新发现的既有问题记录其现状、影响和复现用例，不顺手改变业务结果。

## 5. 验证与完成定义

编写计划前最近一次相关定向记录为 102 passed，其中语言目录契约 13 项；这不是本次重新运行的结果，也不覆盖全部 HTTP/原生场景。完整入口测试此前因缺少 Rust 原生库不能收集。

每批先在当前实现上建立行为刻画，再新增服务入口的失败测试，最后迁移并用相同断言复核。新服务以显式假 I/O 直接调用；兼容门面可复用现有 AST 片段测试方式，但必须明确其未覆盖完整模块导入和 HTTP 分派。

验收分开记录：结构提取完成、隔离回归通过、完整导入/HTTP 集成通过、真实 FM 版本验收。后两级缺失时标明“未验证/受阻”，不能由静态测试或预览图替代。医疗及食堂进入下一批前应补齐对应完整入口回归；原生库缺失时，仅可保留可审阅草稿，不把三批整体标记为完成。

心理辅导当前代码在某些恢复失败路径仍继续尝试退款，关系归档也位于效果提交之后；本计划要求刻画这些现状，不承诺现有代码具备跨账户、原生内存和归档的全局原子性。
